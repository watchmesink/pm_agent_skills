# Preferred PRD Template

Use this as a starting point, then adjust for the feature size and audience.

```markdown
# PRD: [Feature name]

## Situation

[Describe the current landscape, current product behavior, user/workflow challenges, and relevant market movement. Explain why this is the right time to solve the problem. Use prose first. Add a short list of existing capabilities only if it clarifies the current state.]

## Problem

1. [Current problem and consequence.]
2. [Current problem and consequence.]
3. [Current problem and consequence.]

## Solution

[Describe the overall product idea, user-facing behavior, customer value, and product direction. Put detailed behavior in Jobs to be done and keep Requirements lean.]

## Jobs to be done

1. When [situation], I want [capability], so I can [outcome].
2. When [situation], I want [capability], so I can [outcome].
3. When [situation], I want [capability], so I can [outcome].

## Requirements

1. The product must [observable product requirement that defines core behavior without prescribing design or implementation details].
2. The product must [observable product requirement that is necessary for the intended user outcome].
3. The product should [product direction where designers and developers may choose the exact solution].
```
